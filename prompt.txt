## 8. FOOD REQUESTS PAGE

- Request Date

Provide:

- View Requests
- Approve Request
- Reject Request
- Search or filter requests by status

### Request workflow

Preserve the existing business logic:

1. A recipient requests an available donation.
2. The request is initially marked `PENDING`.
3. An authorized user can approve or reject it through the application.
4. On approval, the request becomes `APPROVED`.
5. The corresponding donation becomes `CLAIMED`.
6. On rejection, the request becomes `REJECTED`.
7. A rejected request must not incorrectly mark the donation as claimed.

Do not allow the same donation to be approved for multiple recipients.

If two database updates are required for approval, use an appropriate JDBC transaction so that the request and donation statuses remain consistent.

Do not silently change the database schema.
